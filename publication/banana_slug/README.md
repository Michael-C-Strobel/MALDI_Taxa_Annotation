# Laura Genome Workups

Analysis pipeline for bacterial genome assemblies.

## Setup

Create the conda environment:

```bash
conda env create -f conda_env.yml -p ./conda_env
```

## Data

- `data/16S/` — Per-sample FASTA files containing all 16S rRNA gene copies extracted from genome assemblies (e.g., via Barrnap or RNAmmer). Each file is named `<sample>.16S.fasta`.
- `data/consensus_16S/` — Consensus 16S sequences (one per sample), generated by the pipeline below.
- `data/16S_results/` — BLAST results for each consensus sequence (per-sample TSVs, combined summary, and raw XML).
- `data/16S_analysis/` — Taxonomic analysis: genus/species calls at configurable identity thresholds.
- `data/WGS/` — Whole genome assemblies (FASTA) for all samples.
- `data/16S_clusters/clusters/` — Per-cluster FASTA files from the QC step (one file per organism cluster per sample).
- `data/16S_clusters/metrics/` — QC reports: per-sample summary, per-cluster details, and full JSON.

## Consensus 16S Sequences

Each genome assembly may contain multiple copies of the 16S rRNA gene with minor sequence differences. This step aligns copies within each sample using MUSCLE and calls a majority-rule consensus.

### Run

```bash
bash scripts/run_consensus_16S.sh
```

### Details

The script `bin/make_consensus_16S.py`:

1. Reads each `*.16S.fasta` file from `data/16S/`.
2. If a sample has a single copy, uses it directly as the consensus.
3. If a sample has multiple copies, aligns them with MUSCLE v5 and builds a majority-rule consensus (most frequent base at each aligned column; columns that are majority-gap are excluded).
4. Samples with zero copies are skipped.
5. Writes one `<sample>.consensus_16S.fasta` per sample to `data/consensus_16S/`.

### Options

```
python bin/make_consensus_16S.py --help

  -i, --input-dir    Directory with *.16S.fasta files
  -o, --output-dir   Output directory for consensus FASTAs
  --muscle           Path to MUSCLE executable (default: muscle)
  --min-copies       Minimum copies required (default: 1)
```

## BLAST 16S Identification

Queries each consensus 16S sequence against NCBI's 16S ribosomal RNA database using remote BLAST (megablast). Results are filtered to hits with >= 95% identity.

### Run

```bash
bash scripts/run_blast_16S.sh
```

Additional options can be passed through:

```bash
bash scripts/run_blast_16S.sh --min-identity 97 --max-hits 100
```

### Details

The script `bin/blast_16S.py`:

1. Reads each `*.consensus_16S.fasta` from `data/consensus_16S/`.
2. Submits a remote megablast query against NCBI's `nt` (nucleotide collection) database via Biopython's `NCBIWWW.qblast`.
3. Filters hits to >= 95% identity (configurable via `--min-identity`).
4. Saves per-sample results as TSV files and raw BLAST XML in `data/16S_results/`.
5. Writes a combined `all_results.tsv` with hits from all samples.

**Note:** This step queries NCBI's remote servers and takes several minutes (approximately 1-2 min per sample with rate limiting). An internet connection is required.

### Output

- `data/16S_results/<sample>.blast.tsv` — Filtered hits per sample.
- `data/16S_results/all_results.tsv` — Combined hits from all samples.
- `data/16S_results/xml/<sample>.blast.xml` — Raw BLAST XML for reproducibility.

TSV columns: `sample`, `hit_accession`, `hit_description`, `percent_identity`, `alignment_length`, `query_coverage_pct`, `mismatches`, `gap_opens`, `evalue`, `bit_score`.

### Options

```
python bin/blast_16S.py --help

  -i, --input-dir     Directory with *.consensus_16S.fasta files
  -o, --output-dir    Output directory for BLAST results
  --db                NCBI database (default: nt)
  --min-identity      Minimum percent identity to keep (default: 95.0)
  --max-hits          Max hits per query (default: 50)
  --evalue            E-value threshold (default: 1e-5)
  --delay             Seconds between queries for rate limiting (default: 5)
```

## 16S Taxonomic Analysis

Analyzes BLAST results to identify the most common genus and all genera reported at genus- and species-level identity thresholds. Uses ete3's NCBITaxa to harmonize organism names against the NCBI taxonomy (resolving synonyms and reclassifications, e.g. Burkholderia/Caballeronia).

### Run

```bash
bash scripts/run_16S_analysis.sh
```

Custom thresholds:

```bash
bash scripts/run_16S_analysis.sh --genus-threshold 96 --species-threshold 98.7
```

### Details

The script `bin/16S_analysis.py`:

1. Reads per-sample `*.blast.tsv` files from `data/16S_results/`.
2. Parses candidate organism names from BLAST hit descriptions.
3. Resolves each name to its NCBI-standardized genus and species via ete3 NCBITaxa. On first run, the NCBI taxonomy database is downloaded automatically (~70 MB).
4. At the genus threshold (default >= 95% identity): reports the most common genus, all genera, and species breakdown.
5. At the species threshold (default >= 97% identity): reports the most common genus, top species, all genera, and species breakdown.
6. Hits whose descriptions cannot be resolved to a genus via ete3 are counted as failed name mappings and logged.
7. Writes a per-sample summary, a detailed genus/species breakdown, and a JSON of failed name mappings.

### Output

- `data/16S_analysis/summary.tsv` — One row per sample with total hits, failed name count, top genus, top species, and all genera at each threshold.
- `data/16S_analysis/detail.tsv` — Per-sample genus and species hit counts at each threshold, ranked by frequency.
- `data/16S_analysis/failed_name_mappings.json` — Names that could not be resolved via ete3, with candidates tried, example description, affected samples, and occurrence count.

### Options

```
python bin/16S_analysis.py --help

  -i, --input-dir        Directory with *.blast.tsv files
  -o, --output-dir       Output directory for analysis results
  --genus-threshold      Min identity for genus-level (default: 95.0)
  --species-threshold    Min identity for species-level (default: 97.0)
  --taxdump              Path to taxdump.tar.gz (downloaded automatically if absent)
```

## 16S QC and Cluster Detection

Checks the quality of raw 16S copies and detects mixed/contaminated assemblies where 16S copies originate from multiple organisms. Uses MUSCLE alignment-based pairwise identity (not positional) to avoid artifacts from small indels, and single-linkage clustering to group copies into organism clusters.

### Run

```bash
bash scripts/run_qc_16S.sh
```

To also BLAST a representative from each cluster for identification (slow):

```bash
bash scripts/run_qc_16S.sh --blast-reps
```

### Details

The script `bin/qc_16S.py`:

1. Reads each `*.16S.fasta` file from `data/16S/`.
2. Checks sequence lengths, ambiguous bases, and canonical 16S start (`AGAGTTTGAT...`).
3. Aligns all copies per sample with MUSCLE and computes alignment-based pairwise identities.
4. Clusters copies by single-linkage clustering at a configurable identity threshold (default 90%).
5. Samples with multiple clusters are flagged as `MULTI_ORGANISM` (potential mixed assembly / contamination).
6. Writes per-cluster FASTA files to `data/16S_clusters/clusters/` for downstream use.
7. Optionally BLASTs a representative from each cluster against NCBI nt.

**Note:** All sequences in the input FASTAs are already in sense orientation (canonical 16S 5' start) regardless of their genomic direction (DIR+/DIR-). The DIR annotation is retained as metadata in the cluster details.

### Output

- `data/16S_clusters/clusters/<sample>.cluster_<N>.fasta` — 16S copies belonging to each cluster.
- `data/16S_clusters/metrics/qc_report.tsv` — Per-sample QC summary (copy count, length range, min pairwise identity, cluster count, status).
- `data/16S_clusters/metrics/qc_clusters.tsv` — Per-cluster details (member IDs, source contigs, mean length, BLAST hit if available).
- `data/16S_clusters/metrics/qc_full.json` — Full results for programmatic access.

### Options

```
python bin/qc_16S.py --help

  -i, --input-dir          Directory with *.16S.fasta files
  -o, --output-dir         Base output dir (clusters/ and metrics/ subdirs created)
  --muscle                 Path to MUSCLE executable (default: muscle)
  --identity-threshold     Min identity for same-organism clustering (default: 90.0)
  --blast-reps             BLAST a representative per cluster (default: off)
  --blast-delay            Seconds between BLAST queries (default: 5)
```

## WGS Analysis Pipeline

Standard whole genome analysis: assembly QC, contamination/completeness, AMR screening, MLST typing, and a combined master summary.

### Run all steps

```bash
bash scripts/run_wgs_all.sh --threads 4
```

Or run individual steps:

```bash
bash scripts/run_wgs_quast.sh --threads 4
bash scripts/run_wgs_checkm2.sh --threads 4
bash scripts/run_wgs_abricate.sh
bash scripts/run_wgs_mlst.sh --threads 4
bash scripts/run_wgs_gtdbtk.sh --threads 4
bash scripts/run_wgs_summary.sh
```

### Step 1: Assembly QC (QUAST)

Runs QUAST on each assembly to report contig statistics: total length, N50, GC%, contig count.

- **Script:** `bin/wgs_quast.py`
- **Output:** `data/wgs_quast/summary.tsv` + per-sample QUAST reports in `data/wgs_quast/<sample>/`

### Step 2: Contamination/Completeness (CheckM2)

Runs CheckM2 on all assemblies to estimate genome completeness and contamination using single-copy marker genes. Flags samples as PASS (>=90% complete, <5% contamination), WARN, or FAIL.

On first run, the CheckM2 database (~3.5 GB) is automatically downloaded to `data/checkm2_db/`.

- **Script:** `bin/wgs_checkm2.py`
- **Output:** `data/wgs_checkm2/summary.tsv`

### Step 3: AMR/Virulence Screening (Abricate)

Screens assemblies against multiple databases: NCBI AMRFinderPlus, CARD, ResFinder (AMR genes) and VFDB (virulence factors).

- **Script:** `bin/wgs_abricate.py`
- **Output:** `data/wgs_abricate/amr_summary.tsv`, `data/wgs_abricate/virulence_summary.tsv`, per-database hits in `data/wgs_abricate/<db>/`

### Step 4: MLST Typing

Determines multi-locus sequence type for each assembly (scheme auto-detected).

- **Script:** `bin/wgs_mlst.py`
- **Output:** `data/wgs_mlst/summary.tsv`

### Step 5: Taxonomy Classification (GTDB-tk)

Classifies each genome against the Genome Taxonomy Database (GTDB) using GTDB-tk v2.6.1 `classify_wf`. Reports putative genus and species assignments based on placement in the GTDB reference tree and FastANI comparisons.

On first run, the GTDB-tk reference data (~85 GB) is automatically downloaded to `data/gtdbtk_db/`. A separate conda environment (`conda_env_gtdbtk`) is created automatically.

- **Script:** `bin/wgs_gtdbtk.py`
- **Output:** `data/wgs_gtdbtk/summary.tsv` + raw GTDB-tk output in `data/wgs_gtdbtk/gtdbtk_raw/`

#### Options

```
python bin/wgs_gtdbtk.py --help

  -i, --input-dir       Directory with *.fasta assemblies
  -o, --output-dir      Output directory for GTDB-tk results
  --db                  Path to GTDB-tk reference data (overrides GTDBTK_DATA_PATH)
  --download-db         Download reference data if missing
  --threads             Threads (default: 4)
  --pplacer-threads     Threads for pplacer (default: same as --threads; reduce if memory-limited)
```

### Step 6: Master Summary

Merges all step outputs (including GTDB-tk taxonomy) plus the 16S QC report into a single table. Assigns quality tiers: HIGH (clean, complete), MEDIUM (acceptable), LOW (contaminated or mixed), FAIL (severe issues).

- **Script:** `bin/wgs_summary.py`
- **Output:** `data/wgs_summary/master_summary.tsv`, `data/wgs_summary/flagged_samples.tsv`
